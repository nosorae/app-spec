# 예시 1. 레시피 앱

[앱 기획 표준 v0.1](../SPEC.md) 로 레시피 앱 하나를 처음부터 끝까지 적은 예시다. 서버에서 받아 보여 주는 화면이 대부분인 앱을 이 표준으로 어떻게 적는지 보여 준다. 실제 서비스가 아니라 지어낸 앱이고 서버 주소도 가짜다.

화면 7개, 백그라운드 작업 2개, 알림 1개가 들어 있다. 아래 `yaml` 블록을 전부 이으면 명세 하나가 된다. 검사는 이렇게 한다.

```bash
python3 tools/appspec_check.py examples/recipe-app.md
```

## 앱과 소스

```yaml
앱:
  이름: 예시 레시피 앱
  설명:
    - 레시피를 찾아 보며 요리하고, 저장한 레시피를 만든 크리에이터의 새 레시피 알림을 받는 앱
    - Android 와 iOS 가 이 명세 하나를 같이 쓴다
  시작 화면: 홈
  탭:
    - 홈
    - 저장함
    - 설정
  기본:
    경우:
      로딩: 내용이 들어올 곳에 회색 자리 표시를 보여 준다
      오류: 안내 문구와 다시 시도 버튼을 보여 준다. 버튼을 누르면 그 상태를 새로고침한다
    요청 실패:
      - 안내: 잠시 후 다시 시도해 주세요

소스:
  네트워크:
    콘텐츠 서버:
      주소: https://api.example.com
      인증: 로그인 토큰을 요청 헤더에 붙인다. 응답이 401 이면 로그아웃 동작을 실행한다
      문서: https://api.example.com/docs
  디스크:
    설정 저장소:
      종류: 설정
    앱 디비:
      종류: 디비
    보안 저장소:
      종류: 보안 저장소
```

## 앱 전체가 같이 쓰는 상태와 동작

```yaml
상태:
  로그인 토큰:
    값: 글자. 로그인하지 않았으면 없음
    소스: 디스크
    저장소: 보안 저장소
  로그인함:
    값: 예 또는 아니오
    소스: 계산
    식: 로그인 토큰이 있으면 예
  저장 목록:
    값: 저장한 레시피 목록. 레시피마다 id, 제목, 사진, 저장한 뒤 바뀜 여부
    소스: 네트워크
    요청: GET /me/saved
    갱신:
      - 저장함 화면에 들어올 때
    보관: 앱 디비
    비움: 로그아웃할 때
  새 레시피 알림 받기:
    설명: 기기에 저장한 값이 기준이다. 바꿀 때마다 서버에 알린다
    값: 예 또는 아니오. 처음에는 예
    소스: 디스크
    저장소: 설정 저장소
  알림 권한:
    값: 허용, 거부, 아직 묻지 않음
    소스: 기기
    기능: 알림 권한
  네트워크 연결:
    값: 연결됨 또는 끊김
    소스: 기기
    기능: 네트워크 연결 상태
  밀린 완료 기록:
    값: 서버에 아직 보내지 못한 단계 id 목록
    소스: 디스크
    저장소: 앱 디비
    비움: 로그아웃할 때

동작:
  로그아웃:
    한다:
      - 요청: DELETE /me/push-token
        실패하면:
          - 실패해도 아래 단계를 이어서 한다
      - 변경: 로그인 토큰
        값: 없음
      - 이동: 홈
        방식: 비우고 이동
  푸시 토큰 등록:
    설명: 서버가 이 기기로 새 레시피 알림을 보낼 수 있게 기기의 푸시 토큰을 알린다
    언제: 앱을 켤 때
    조건: 로그인함이 예다
    한다:
      - 기기: 푸시 토큰을 받는다
        성공하면:
          - 요청: PUT /me/push-token (받은 푸시 토큰)
  알림 권한 묻기:
    설명: 새 레시피 알림을 받으려면 권한이 필요하다. 처음 레시피를 저장했을 때 한 번만 묻는다. 거부하면 설정 화면의 스위치 아래에 안내가 보인다
    조건: 알림 권한이 아직 묻지 않음이다
    한다:
      - 기기: 알림 권한을 요청한다
```

## 화면

```yaml
화면:
  홈:
    설명: 추천 레시피를 보여 주는 첫 탭
    디자인: https://design.example.com/home

            언제: 당겨서 새로고침

        요청: GET /recipes/{레시피 id}/steps?unit={단위}
        갱신:
          - 화면에 들어올 때
          - 다른 화면에서 돌아올 때
          - 단위가 바뀔 때
        보관: 메모리
      단위:
        값: 계량컵 또는 그램. 처음에는 계량컵
        소스: 메모리
        구성 변경에도 유지: 예
        프로세스 종료에도 유지: 예
    컴포넌트:
      레시피 정보:
        표시:
          - 레시피.사진
          - 레시피.제목
          - 레시피.크리에이터
          - 레시피.소개

        표시: 레시피.저장 여부

          레시피.저장 여부가 아니오일 때: 빈 책갈피 아이콘
        동작:
          로그인으로 보내기:
            언제: 탭
            설명: 로그인하고 돌아온 뒤 저장은 다시 눌러야 한다
            조건: 로그인함이 아니오다
            한다:
              - 이동: 로그인
          저장하기:
            언제: 탭
            조건: 로그인함이 예이고 레시피.저장 여부가 아니오다
            한다:
              - 변경: 레시피.저장 여부
                값: 예

                성공하면:
                  - 새로고침: 저장 목록

                실패하면:

            조건: 로그인함이 예이고 레시피.저장 여부가 예다
            한다:
              - 변경: 레시피.저장 여부
                값: 아니오

                성공하면:
                  - 새로고침: 저장 목록
                실패하면:
                  - 변경: 레시피.저장 여부
                    값: 예
                  - 안내: 저장을 풀지 못했어요. 잠시 후 다시 시도해 주세요
      단위 버튼:
        종류: 버튼
        표시: 단위
        동작:
          단위 바꾸기:
            언제: 탭
            한다:
              - 변경: 단위
                값: 지금 값의 반대
      단계 목록:
        종류: 목록
        표시: 단계 목록
        경우:
          비었음: 아직 적힌 단계가 없어요 문구를 보여 준다
        컴포넌트:
          단계 줄:
            표시:
              - 항목.제목
              - 항목.걸리는 시간
            경우:
              해 본 단계일 때: 제목을 회색으로 보여 준다
            동작:
              단계 열기:
                언제: 탭
                한다:
                  - 이동: 요리 모드
                    넘기는 값:
                      레시피 id: 레시피 id
                      단계 id: 항목.id

  요리 모드:
    설명:
      - 단계 하나의 과정 사진을 세로로 이어 보여 준다
      - 요리하는 동안 화면이 꺼지지 않게 한다
    받는 값:
      - 레시피 id
      - 단계 id
    링크: /recipes/{레시피 id}/steps/{단계 id}
    상태:
      과정 사진 목록:
        값: 과정 사진 주소 목록
        소스: 네트워크

          - 화면에 들어올 때
        보관: 메모리

        값: 단계마다 따로 두는 마지막으로 본 사진 번호. 처음에는 1

        저장소: 앱 디비
        비움: 로그아웃할 때

            한다:

        컴포넌트:
          뒤로 버튼:
            종류: 버튼
            동작:
              나가기:
                언제: 탭
                한다:
                  - 이동: 뒤로

  저장함:
    설명: 저장한 레시피를 모아 보는 탭. 연결이 끊겨도 마지막으로 받은 목록을 보여 준다
```

## 백그라운드 작업과 알림

```yaml
백그라운드 작업:
  밀린 완료 기록 보내기:
    설명: 연결이 없어 보내지 못한 완료 기록을 나중에 한꺼번에 보낸다
    언제: 요리 모드의 단계 완료 보내기가 실패해서 예약했을 때
    미뤄도 됨: 예
    조건:
      - 네트워크에 연결돼 있다
    한다:
      - 요청: POST /steps/done-batch (밀린 완료 기록 전부)
        성공하면:
          - 변경: 밀린 완료 기록
            값: 빈 목록
    다시 시도: 간격을 두 배씩 늘려 가며 다섯 번까지
    겹치면: 건너뜀
  저장한 레시피 미리 받기:
    설명: 부엌에서 연결이 끊겨도 저장함이 최신에 가깝게 보이도록 하루에 한 번 미리 받아 둔다
    언제: 하루에 한 번
    미뤄도 됨: 예
    조건:
      - 와이파이에 연결돼 있다
      - 로그인함이 예다
    한다:
      - 새로고침: 저장 목록
    다시 시도: 안 함. 다음 날 다시 돈다
    겹치면: 건너뜀

알림:
  새 레시피 알림:
    설명: 저장한 레시피를 만든 크리에이터가 새 레시피를 올리면 서버가 보낸다. 새 레시피 알림 받기가 아니오인 사용자에게는 서버가 보내지 않는다. 본문 아래 줄에 받은 레시피 제목을 보여 준다
    보내는 곳: 서버
    받는 값:
      - 레시피 id
      - 레시피 제목
      - 크리에이터 이름
    분류: 새 레시피
    중요도: 보통
    제목: 받은 크리에이터 이름을 그대로 보여 준다
    본문: 새 레시피가 올라왔어요
    앱을 보고 있을 때: 시스템 알림으로 띄우지 않고 화면 위쪽에 같은 내용의 띠를 3초 보여 준다. 띠를 누르면 알림을 눌렀을 때와 같다
    동작:
      새 레시피 열기:
        언제: 탭
        한다:
          - 이동: 레시피 상세
            넘기는 값:
              레시피 id: 레시피 id
```
