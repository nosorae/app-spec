# 예시 1. 카페 픽업 주문 앱

[앱 기획 쓰는 법 v0.1](../SPEC.md) 로 카페 픽업 주문 앱 하나를 처음부터 끝까지 적은 예시다. 메뉴를 골라 장바구니에 담고, 서버에 주문을 넣고, 주문 상태를 받아 보는 앱을 이 형식으로 어떻게 적는지 보여 준다. 실제 서비스가 아니라 지어낸 앱이고 서버 주소도 가짜다.

화면 7개, 흐름 1개, 백그라운드 작업 2개, 알림 1개가 들어 있다. 아래 `yaml` 블록을 전부 이으면 명세 하나가 된다. 검사는 이렇게 한다.

```bash
python3 tools/appspec_check.py examples/cafe-order-app.md
```

## 앱과 소스

```yaml
앱:
  이름: 예시 카페 픽업 주문 앱
  설명:
    - 매장을 고르고 메뉴를 주문한 뒤, 준비되면 알림을 받고 매장에서 찾아가는 앱
    - 결제는 매장에서 한다. 예시를 짧게 하려고 앱 안 결제는 뺐다
    - Android 와 iOS 가 이 명세 하나를 같이 쓴다
  시작 화면: 메뉴
  탭:
    - 메뉴
    - 장바구니
    - 설정
  기본:
    경우:
      로딩: 내용이 들어올 곳에 회색 자리 표시를 보여 준다
      오류: 안내 문구와 다시 시도 버튼을 보여 준다. 버튼을 누르면 그 상태를 새로고침한다
    요청 실패:
      - 안내: 잠시 후 다시 시도해 주세요

소스:
  네트워크:
    주문 서버:
      주소: https://api.example.com
      인증: 로그인 토큰을 요청 헤더에 붙인다. 응답이 401 이면 로그아웃 동작을 실행한다
      문서: https://api.example.com/docs
  디스크:
    설정 저장소:
      종류: 설정
    앱 디비:
      종류: 디비
    보안 저장소:
      종류: 보안 저장소
```

## 앱 전체가 같이 쓰는 상태와 동작

```yaml
상태:
  로그인 토큰:
    값: 글자. 로그인하지 않았으면 없음
    소스: 디스크
    저장소: 보안 저장소
  로그인함:
    값: 예 또는 아니오
    소스: 계산
    식: 로그인 토큰이 있으면 예
  메뉴 목록:
    값: 메뉴 목록. 메뉴마다 id, 이름, 사진, 가격, 품절 여부
    소스: 네트워크
    요청: GET /menus
    갱신:
      - 메뉴 화면에 들어올 때
    보관: 앱 디비
  장바구니 메뉴:
    설명: 메뉴 상세에서 담고 장바구니에서 본다. 앱을 껐다 켜도 남는다
    값: 담은 메뉴 목록. 메뉴마다 메뉴 id, 이름, 고른 옵션, 수량, 가격. 처음에는 빈 목록
    소스: 디스크
    저장소: 앱 디비
    비움: 로그아웃할 때
  즐겨찾기 메뉴:
    설명: 기기에 저장한 값이 기준이다. 바꿀 때마다 즐겨찾기 보내기 작업이 서버에 알린다
    값: 즐겨찾기한 메뉴 id 목록. 처음에는 빈 목록
    소스: 디스크
    저장소: 앱 디비
    비움: 로그아웃할 때
  주문 알림 받기:
    설명: 기기에 저장한 값이 기준이다. 바꿀 때마다 서버에 알린다
    값: 예 또는 아니오. 처음에는 예
    소스: 디스크
    저장소: 설정 저장소
  알림 권한:
    값: 허용, 거부, 아직 묻지 않음
    소스: 기기
    기능: 알림 권한
  네트워크 연결:
    값: 연결됨 또는 끊김
    소스: 기기
    기능: 네트워크 연결 상태

동작:
  로그아웃:
    한다:
      - 요청: DELETE /me/push-token
        실패하면:
          - 실패해도 아래 단계를 이어서 한다
      - 취소: 즐겨찾기 보내기
      - 변경: 로그인 토큰
        값: 없음
      - 이동: 메뉴
        방식: 비우고 이동
  푸시 토큰 등록:
    설명: 서버가 이 기기로 주문 준비 완료 알림을 보낼 수 있게 기기의 푸시 토큰을 알린다
    언제: 앱을 켤 때
    조건: 로그인함이 예다
    한다:
      - 기기: 푸시 토큰을 받는다
        성공하면:
          - 요청: PUT /me/push-token (받은 푸시 토큰)
  알림 권한 묻기:
    설명: 주문 준비 완료 알림을 받으려면 권한이 필요하다. 처음 주문했을 때 한 번만 묻는다. 거부하면 설정 화면의 스위치 아래에 안내가 보인다
    조건: 알림 권한이 아직 묻지 않음이다
    한다:
      - 기기: 알림 권한을 요청한다
```

## 흐름

```yaml
흐름:
  주문하기:
    설명: 장바구니에서 매장 선택을 열어 매장을 고르면 장바구니로 돌아와 고른 매장이 보인다. 장바구니는 탭이라 늘 열려 있으므로, 앱이 켜져 있는 동안 고른 매장이 남는다
    화면:
      - 장바구니
      - 매장 선택
    상태:
      고른 매장:
        값: 매장 하나. id, 이름. 처음에는 없음
        소스: 메모리
        구성 변경에도 유지: 예
        프로세스 종료에도 유지: 예
```

```yaml

        종류: 버튼

          당겨서 새로 받기:
            언제: 당겨서 새로고침
            한다:
              - 새로고침: 메뉴 목록
        컴포넌트:
          메뉴 카드:
            표시:
              - 항목.사진
              - 항목.이름
              - 항목.가격

              즐겨찾기만 보기가 예이고 즐겨찾기 메뉴에 없는 메뉴일 때: 숨긴다
              품절된 메뉴일 때: 흐리게 보여 주고 품절 표시를 붙인다
            동작:
              상세 열기:
                언제: 탭
                한다:
                  - 이동: 메뉴 상세
                    넘기는 값:
                      메뉴 id: 항목.id

  메뉴 상세:
    설명: 메뉴 하나의 옵션을 골라 장바구니에 담는다
    받는 값:
      - 메뉴 id
    링크: /menus/{메뉴 id}
    상태:
      고른 옵션:
        설명: 화면을 돌리거나 다른 앱을 쓰다 돌아와도 고르던 옵션이 남는다
        값: 온도, 크기, 샷 추가. 처음에는 메뉴의 기본 옵션
        소스: 메모리
        구성 변경에도 유지: 예
        프로세스 종료에도 유지: 예
      즐겨찾기 여부:
        값: 예 또는 아니오
        소스: 계산
        식: 즐겨찾기 메뉴에 메뉴 id 가 있으면 예
      메뉴:
        값: 메뉴 하나. 이름, 사진, 설명, 가격, 고를 수 있는 옵션, 품절 여부
        소스: 네트워크
        요청: GET /menus/{메뉴 id}
        갱신:
          - 화면에 들어올 때
        보관: 메모리
    컴포넌트:
      메뉴 정보:
        표시:
          - 메뉴.사진
          - 메뉴.이름
          - 메뉴.설명
          - 메뉴.가격
      즐겨찾기 버튼:
        종류: 버튼
        표시: 즐겨찾기 여부
        경우:
          즐겨찾기 여부가 예일 때: 채워진 별 아이콘
          즐겨찾기 여부가 아니오일 때: 빈 별 아이콘
        동작:
          로그인으로 보내기:
            언제: 탭
            설명: 로그인하고 돌아온 뒤 즐겨찾기는 다시 눌러야 한다
            조건: 로그인함이 아니오다
            한다:
              - 이동: 로그인
          즐겨찾기 바꾸기:
            언제: 탭
            조건: 로그인함이 예다
            한다:
              - 변경: 즐겨찾기 메뉴
                값: 메뉴 id 가 있으면 빼고 없으면 더한다
              - 예약: 즐겨찾기 보내기
              - 분석: favorite_toggle (메뉴 id)
      옵션 고르기:
        종류: 옵션 선택
        표시: 고른 옵션
        설명: 메뉴.고를 수 있는 옵션에 있는 것만 보여 준다
        동작:
          옵션 바꾸기:
            언제: 탭
            한다:
              - 변경: 고른 옵션
                값: 누른 옵션으로 바꾼다
      담기 버튼:
        종류: 버튼
        문구: 장바구니에 담기
        경우:
          메뉴.품절 여부가 예일 때: 흐리게 보여 주고 누를 수 없게 한다
        동작:
          담기:
            언제: 탭
            한다:
              - 변경: 장바구니 메뉴
                값: 이 메뉴와 고른 옵션을 수량 1로 더한다. 같은 메뉴와 옵션이 이미 있으면 그 수량에 1을 더한다
              - 분석: cart_add (메뉴 id)
              - 안내: 장바구니에 담았어요
              - 이동: 뒤로

  장바구니:
    설명: 담은 메뉴를 확인하고 매장을 골라 주문하는 탭
    상태:
      합계 금액:
        값: 원 단위 숫자
        소스: 계산
        식: 장바구니 메뉴마다 가격과 수량을 곱해 모두 더한다
    컴포넌트:
      매장 버튼:
        종류: 버튼
        표시: 고른 매장
        경우:
          고른 매장이 없음일 때: 매장을 골라 주세요 문구를 보여 준다
        동작:
          매장 고르기:
            언제: 탭
            한다:
              - 이동: 매장 선택
      장바구니 목록:
        종류: 목록
        표시: 장바구니 메뉴
        경우:
          비었음:
            문구: 장바구니가 비어 있어요
            컴포넌트:
              메뉴로 버튼:
                종류: 버튼
                문구: 메뉴 보러 가기
                동작:
                  메뉴로 가기:
                    언제: 탭
                    한다:
                      - 이동: 메뉴
        컴포넌트:
          장바구니 줄:
            표시:
              - 항목.이름
              - 항목.고른 옵션
              - 항목.수량
              - 항목.가격
            컴포넌트:
              더하기 버튼:
                종류: 버튼
                문구: 하나 더
                동작:
                  수량 늘리기:
                    언제: 탭
                    한다:
                      - 변경: 항목.수량
                        값: 지금 값에 1을 더한다
              빼기 버튼:
                종류: 버튼
                문구: 빼기
                동작:
                  빼기:
                    언제: 탭
                    한다:
                      - 변경: 장바구니 메뉴
                        값: 이 항목을 뺀다
      합계:
        표시: 합계 금액
      주문 버튼:
        종류: 버튼
        문구: 주문하기
        경우:
          장바구니 메뉴가 비었거나 고른 매장이 없음일 때: 흐리게 보여 주고 누를 수 없게 한다
        동작:
          로그인으로 보내기:
            언제: 탭
            조건: 로그인함이 아니오다
            한다:
              - 이동: 로그인
          주문하기:
            언제: 탭
            조건: 로그인함이 예다
            겹치면: 건너뜀
            한다:
              - 요청: POST /orders (고른 매장, 장바구니 메뉴)
                성공하면:
                  - 변경: 장바구니 메뉴
                    값: 빈 목록
                  - 분석: order_place (응답으로 받은 주문 id)
                  - 실행: 알림 권한 묻기
                  - 이동: 주문 현황
                    넘기는 값:
                      주문 id: 응답으로 받은 주문 id
                실패하면:
                  - 조건: 품절된 메뉴가 있다
                    안내: 품절된 메뉴가 있어요. 장바구니를 확인해 주세요
                  - 조건: 그 밖의 실패
                    안내: 주문하지 못했어요. 잠시 후 다시 시도해 주세요

  매장 선택:
    형태: 바텀시트
    설명: 픽업할 매장을 고른다. 고르면 시트를 닫고 장바구니로 돌아간다
    상태:
      매장 목록:
        값: 매장 목록. 매장마다 id, 이름, 주소, 지금 문을 열었는지
        소스: 네트워크
        요청: GET /stores
        갱신:
          - 화면에 들어올 때
        보관: 메모리
    컴포넌트:
      매장 목록:
        종류: 목록
        표시: 매장 목록
        경우:
          비었음: 이 경우는 없다. 매장은 1곳 이상 있다
        컴포넌트:
          매장 줄:
            표시:
              - 항목.이름
              - 항목.주소
            경우:
              지금 문을 닫은 매장일 때: 흐리게 보여 주고 누를 수 없게 한다
            동작:
              매장 고르기:
                언제: 탭
                한다:
                  - 변경: 고른 매장
                    값: 누른 매장
                  - 이동: 뒤로
```

## 백그라운드 작업과 알림

```yaml
백그라운드 작업:
  즐겨찾기 보내기:
    설명: 즐겨찾기를 바꾸면 기기에 먼저 저장하고 서버에는 이 작업이 알린다. 연결이 없으면 연결될 때까지 기다린다. 매번 목록 전부를 보내므로 마지막 것 하나만 보내면 된다
    언제: 메뉴 상세의 즐겨찾기 바꾸기에서 예약했을 때
    미뤄도 됨: 예
    조건:
      - 네트워크에 연결돼 있다
      - 로그인함이 예다
    한다:
      - 요청: PUT /me/favorites (즐겨찾기 메뉴 전부)
    다시 시도: 간격을 두 배씩 늘려 가며 다섯 번까지
    겹치면: 바꿈
  메뉴 목록 미리 받기:
    설명: 연결이 약한 매장 안에서도 메뉴를 볼 수 있게 하루에 한 번 미리 받아 둔다
    언제: 하루에 한 번
    미뤄도 됨: 예
    조건:
      - 와이파이에 연결돼 있다
    한다:
      - 새로고침: 메뉴 목록
    다시 시도: 안 함. 다음 날 다시 돈다
    겹치면: 건너뜀

알림:
  주문 준비 완료 알림:
    설명: 매장에서 메뉴를 다 만들면 서버가 보낸다. 주문 알림 받기가 아니오인 사용자에게는 서버가 보내지 않는다
    보내는 곳: 서버
    받는 값:
      - 주문 id
      - 주문 번호
      - 매장 이름
    분류: 주문 상태
    중요도: 높음
    제목: 받은 매장 이름을 그대로 보여 준다
    본문: 주문하신 메뉴가 준비됐어요
    앱을 보고 있을 때: 그 주문의 주문 현황을 보고 있으면 아무것도 띄우지 않는다. 화면의 주문 상태는 서버가 보낸 값으로 이미 바뀌어 있다. 다른 화면이면 화면 위쪽에 같은 내용의 띠를 3초 보여 준다. 띠를 누르면 알림을 눌렀을 때와 같다
    동작:
      주문 현황 열기:
        언제: 탭
        한다:
          - 이동: 주문 현황
            넘기는 값:
              주문 id: 주문 id
```
